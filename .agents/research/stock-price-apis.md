# Lean on Yahoo, back it with BYOK

As of November 2026, the only keyless source that gives both a current price and a daily close for a past date across all three markets (BIST `.IS` in TRY, NYSE/NASDAQ, and Xetra/Euronext/LSE) is **Yahoo Finance's undocumented v8 chart endpoint**. It answered every test ticker with HTTP 200 and no key or crumb, and one `range=1y` call returns a whole year of daily closes. It is also legally and technically fragile: Yahoo's terms forbid automated collection, `query1`'s robots.txt is `Disallow: /`, and in 2024–2025 it repeatedly throttled non-browser clients for days at a time. No free keyed provider can stand in for it with a key shipped in the binary. Every free tier is personal or non-commercial, bans credential sharing, and has a quota (20–800 calls/day) that a few hundred installs would use up. Most free tiers also cover only US listings. The workable design has four parts. Yahoo is the default primary. Market-specific keyless fallbacks back it up: İş Yatırım and TradingView for BIST, Nasdaq's site API for the US. A **bring-your-own-key (BYOK)** slot lets a user plug in their own key, with EODHD the best global choice and Tiingo the only provider that explicitly endorses BYOK. Manual price entry is the last resort. Because a past day's close never changes once it is in `.cache/history.json`, the fallback chain mostly has to cover *today's* price and the one-off backfill when a holding is added, not the whole history. The weakest market is the EU, not BIST: Yahoo is the only keyless source of EU history, so a user-supplied EODHD key matters most there.

## Yahoo's v8 chart endpoint covers every market with one keyless call

The endpoint `query1|query2.finance.yahoo.com/v8/finance/chart/{symbol}` returned HTTP 200 for AAPL, VOO, THYAO.IS, SAP.DE, MC.PA, ASML.AS, IWDA.AS, SHEL.L and VUSA.L on 2026-11-12. Each response carried `meta.currency`, `meta.regularMarketPrice`, `meta.regularMarketTime`, the exchange name and the exchange timezone ([live call](https://query1.finance.yahoo.com/v8/finance/chart/THYAO.IS?range=5d&interval=1d)). For THYAO.IS it reported **`"currency":"TRY"`, exchange `IST`, timezone `Europe/Istanbul`**. History works the same way. A `period1/period2` window for THYAO in early November 2025 returned five session timestamps with `indicators.quote[0].close` and `indicators.adjclose[0].adjclose` arrays. AAPL `range=1y&interval=1d` returned **251 daily points** covering 2025-11-12 to 2026-11-11 ([live call](https://query1.finance.yahoo.com/v8/finance/chart/AAPL?range=1y&interval=1d)). The data cross-checks cleanly against independent sources. Yahoo's AAPL price of 355.63 matched Nasdaq's 11/11/2026 close exactly ([Nasdaq live call](https://api.nasdaq.com/api/quote/AAPL/historical?assetclass=stocks&fromdate=2025-11-12&todate=2026-11-11&limit=9999)). Yahoo's ASELS.IS closes for 1–9 October 2026 (370.0, 362.75, 371.5, 376.0, 348.75, 348.75, 351.25) were **identical to İş Yatırım's** ([İş Yatırım live call](https://www.isyatirim.com.tr/_layouts/15/Isyatirim.Website/Common/Data.aspx/HisseTekil?hisse=ASELS&startdate=01-10-2026&enddate=10-10-2026)). Unknown symbols return a clean **404** with `"No data found, symbol may be delisted"`. Every other Yahoo endpoint (v7 quote, v10 quoteSummary, v7 download) now returns 401 for a missing crumb or login, so v8 chart is the only open door ([live call](https://query1.finance.yahoo.com/v7/finance/quote?symbols=AAPL)).

Two behaviours matter for a ureq client. First, **an empty User-Agent gets HTTP 429**, while ureq's default `ureq/2.10.0` UA and a `Rust-reqwest/0.12` UA both got 200. curl's default UA also drew a 429 ("Edge: Too Many Requests") in one test, so the client should always send an explicit, stable UA. Second, a burst of 40 sequential plus 50 parallel requests drew no 429 from one IP. Yahoo publishes no rate limit, though, and the history is not reassuring. In April–May 2025, Python clients were throttled while browsers and curl kept working. The yfinance community traced this to **TLS fingerprinting** and fixed it by impersonating Chrome through `curl_cffi` ([yfinance #2422](https://github.com/ranaroussi/yfinance/issues/2422)). The desktop app Portfolio Performance saw days of 429s in the same period ([PP forum](https://forum.portfolio-performance.info/t/yahoo-finance-too-many-requests-getting-errors-on-updates-desktop-only/32780)). ureq's rustls fingerprint cannot impersonate a browser, so if Yahoo turns fingerprinting back on, the Rust client breaks with no quick fix. That is the main reason the fallback chain exists. The current yfinance tracker is calmer: issues closed between July and November 2026 report data-quality problems rather than blocking. Examples are a **missing 2026-08-28 daily session across many tickers** and NaN OHLC on the latest bar before the open ([yfinance issues](https://github.com/ranaroussi/yfinance/issues?q=is%3Aissue+sort%3Acreated-desc)).

The legal position is weak and should be disclosed. Yahoo's terms prohibit accessing or collecting data "using any automated means … for any purpose without our express, prior permission" and forbid distributing or commercially exploiting any part of the Services ([Yahoo Terms](https://legal.yahoo.com/us/en/yahoo/terms/otos/index.html)). Yahoo also says its data is "for informational purposes only, and is not intended for trading or investing purposes" ([Yahoo Help SLN2310](https://help.yahoo.com/kb/SLN2310.html)). Mature open-source tools still default to it. Ghostfolio's default `DATA_SOURCES` is `[COINGECKO, MANUAL, YAHOO]` ([Ghostfolio config](https://github.com/ghostfolio/ghostfolio/blob/main/apps/api/src/services/configuration/configuration.service.ts)), and Portfolio Performance and Wealthfolio both ship Yahoo feeds. The defensible stance for a free personal app is that each user's machine fetches its own holdings at very low volume, with Yahoo named as an unofficial source in settings. For a paid app, the safer stance is to make a user-supplied key the primary and leave Yahoo as an opt-in.

## Most keyless alternatives are dead, US-only or blocked by bot walls

**Stooq is gone** for programmatic use. Since March 2026 it requires a CAPTCHA-issued API key ([pandas-datareader #1012](https://github.com/pydata/pandas-datareader/issues/1012)), and on 2026-11-12 every CSV URL returned a 200 response with an HTML SHA-256 proof-of-work challenge instead of data ([live call](https://stooq.com/q/d/l/?s=aapl.us&i=d&d1=20251103&d2=20251107)). That a 200 can carry HTML is itself a design lesson. Google Finance has no API: the legacy JSON redirects, and Google states that GOOGLEFINANCE historical data "cannot be downloaded or accessed via the Sheets API or Apps Script" ([Google Docs Help](https://support.google.com/docs/answer/3093281)). Euronext Live now returns an encrypted `{"ct":"…"}` blob, Investing.com and MarketWatch return 403/401 bot walls, and FT and Business Insider are HTML-only ([Euronext live call](https://live.euronext.com/en/ajax/getDetailedQuote/FR0000121014-XPAR)).

Three keyless sources still work but each has a narrow scope. The **Nasdaq.com API** serves US stocks and ETFs, current and about five years of daily history, keyless. Its prices are strings with inconsistent `$` prefixes (stocks have them, ETFs don't), and it has a quirk: short past windows return zero rows, while a window from D to today returns full data ([live call](https://api.nasdaq.com/api/quote/AAPL/info?assetclass=stocks)). It also hung on curl's default UA but answered ureq's. Its ToS could not be retrieved. **CNBC's quote and bar APIs** cover US and Xetra but not BIST. NBCUniversal's terms forbid scraping or integrating its data into other products ([NBCU Terms](https://www.cnbc.com/nbcuniversal-terms-of-service/)), so it is excluded. The **Börse Frankfurt API** returns current Xetra and Frankfurt prices by ISIN plus MIC ([live call](https://api.boerse-frankfurt.de/v1/data/price_information/single?isin=DE0007164600&mic=XETR)). Its history endpoint returned `{}`, which looks like header-based gating, so it is at most an optional current-price check for German listings.

### BIST has two keyless backups, both unofficial

Borsa Istanbul itself offers no free API. Market data reaches the public "through Borsa İstanbul's licensed data vendors" ([BIST Data Dissemination](https://www.borsaistanbul.com/en/data/data-dissemination)), and historical files are sold through the login-based DataStore shop ([BIST Equity Market Data](https://www.borsaistanbul.com/en/data/equity-market-data)). The main site reset TLS connections from the research machine, which casts doubt on any plan to download official files. TCMB's EVDS carries BIST indices but no individual stocks, and its old evds2 REST API closed at the end of 2025. The replacement needs a per-user key ([borsapy releases](https://github.com/saidsurucu/borsapy/releases)).

Two broker or charting endpoints fill the gap. **İş Yatırım's `HisseTekil`** returns daily OHLC, volume, the USD/TRY rate and a USD-based price for a `DD-MM-YYYY` date range ([live call](https://www.isyatirim.com.tr/_layouts/15/Isyatirim.Website/Common/Data.aspx/HisseTekil?hisse=ASELS&startdate=01-10-2026&enddate=10-10-2026)). **`OneEndeks`** returns a last price about 15 minutes delayed, plus `dayClose`, `weekClose` and `yearClose` ([live call](https://www.isyatirim.com.tr/_layouts/15/Isyatirim.Website/Common/Data.aspx/OneEndeks?endeks=THYAO)). Both live under `/_layouts/`, which İş Yatırım's robots.txt disallows ([robots.txt](https://www.isyatirim.com.tr/robots.txt)). Errors come back as HTTP 200 with `"ok":false`, and the endpoints are intermittently slow: borsa-mcp raised its timeout to 15 s after 5 s probes timed out ([borsa-mcp PR #3](https://github.com/biNom-Highend-Engineering/borsa-mcp/pull/3)). The **TradingView scanner** (`POST scanner.tradingview.com/turkey/scan`) returns keyless current closes in TRY, labelled `delayed_streaming_900`, for many tickers in one request. It has no date-range history, and its ToS was not reviewed ([borsapy README](https://github.com/saidsurucu/borsapy)). Bigpara (403 from MerlinCDN), investing.com (Cloudflare) and mynet (robots-disallowed `/api/`) are out. borsapy's 2026 changelog shows the maintenance cost of this ecosystem: TEFAS was rewritten in April and broke its legacy endpoints, and EVDS moved backends in May. That works out to several breaking upstream changes a year ([borsapy releases](https://github.com/saidsurucu/borsapy/releases)).

## No free keyed tier allows a shipped key; BYOK is the only clean model

Exchange licensing is not the blocker. At NYSE, Nasdaq, Deutsche Börse, Euronext and LSE, 15-minute delayed and end-of-day data carry no per-user display fees. Deutsche Börse's 2026 price list says flatly that "No Data Fees are charged for Delayed Data" ([DB MDDA Price List 2026](https://www.mds.deutsche-boerse.com/resource/blob/4694154/8d7eccd97e978f07f993cc8b7a0ae4a1/data/MDDA_Price_List_15_2.pdf)). BIST lets sub-distributors obtain delayed data that is "not subject to per-user fees" ([BIST FAQ](https://borsaistanbul.com/sss/veri-dagitim-ve-endeks-lisanslama)). The obligations fall on the vendor, which passes them to whoever holds the API key. Nasdaq requires a visible delay notice such as "Data Delayed 15 minutes" on displays of delayed data ([Nasdaq US Data Policies v2.6](https://www.nasdaqtrader.com/content/AdministrationSupport/Policy/USEquitiesandOptionsDataPolicies.pdf)). The app should therefore label prices "Delayed" or "Close as of {date}".

The vendor terms are the binding constraint, and they are uniform. Twelve Data forbids using "Free Tier data for commercial purposes" and sharing credentials, and allows redistribution only with an add-on ([Twelve Data Terms](https://twelvedata.com/terms)). FMP forbids integrating data "into any tools or applications accessible by any third parties" ([FMP ToS](https://site.financialmodelingprep.com/terms-of-service)). EODHD bans "Sharing access to their account with others" ([EODHD Terms](https://eodhd.com/financial-apis/terms-conditions)). Massive (formerly Polygon) restricts use to "your own personal applications" and bans shared credentials ([Massive ToS](https://massive.com/legal/individuals-terms-of-service)). A key embedded in the binary is shared with every user and can be extracted by any of them. Under **BYOK**, each user becomes the licensee using data privately. **Tiingo is the only provider that explicitly endorses this pattern**: "Each user must have their own API token" and "Tiingo must be clearly attributed as the data source" ([Tiingo developer appendix](https://www.tiingo.com/documentation/appendix/developers)).

Two traps stand out. **IEX Cloud is dead** (shut down 2024-08-31) ([Waters Technology](https://waterstechnology.com/data-management/7951882/iex-cloud-closure-forces-fintech-clients-to-seek-data-alternatives)), and Nasdaq Data Link's free WIKI table has been frozen since 2018 ([Eulerpool](https://eulerpool.com/financial-data-api/quandl-alternative)). Twelve Data's **THYAO is a free "sample" symbol while the other 654 BIST stocks need Grow**, so a test with THYAO on a free key will pass and then mislead. BIST through EODHD's free tier remains the main unverified question: the demo key is locked to US samples, so confirming `THYAO.IS` needs a registered key.

## The recommended chain differs by market, with EU the thinnest

Each link below is tried only for instruments and dates the previous link could not serve. Past dates that are already in the cache are never re-fetched.

| Market | Current price | Close on past date D | Notes |
|---|---|---|---|
| **BIST** (`XIST`, TRY) | Yahoo `THYAO.IS` → İş Yatırım `OneEndeks` → TradingView scanner `BIST:THYAO` → EODHD BYOK → manual | Yahoo → İş Yatırım `HisseTekil` → EODHD BYOK → manual | Two independent keyless paths; values cross-validated |
| **US** (`XNYS`/`XNAS`/`ARCX`) | Yahoo → Nasdaq API → BYOK (Tiingo / Twelve Data / EODHD) → manual | Yahoo → Nasdaq historical (fetch D..today, filter) → BYOK Tiingo / EODHD → manual | Best covered; free BYOK tiers all work |
| **EU** (`XETR`, `XPAR`, `XAMS`, `XLON`) | Yahoo → EODHD BYOK → Börse Frankfurt (German listings only, by ISIN) → manual | Yahoo → EODHD BYOK (1-year window fits the need) → manual | **No keyless history fallback**; BYOK matters most here |

The request budget is small. One Yahoo `range=1y` call per ticker backfills a full year, and after that each refresh costs one call per ticker for today. Yahoo's `range=5d` covers the case where the app was closed over a weekend. A 20-holding portfolio fits even EODHD's free 20 calls/day once the 500-call welcome bonus has paid for the backfill. A slow İş Yatırım endpoint should get a longer per-attempt timeout (around 15 s) than the 10 s the app uses elsewhere.

## Feed design: a canonical listing key, raw closes, and the last bar on or before D

**Symbology.** Make the canonical key **(ticker, ISO 10383 MIC)**, store ISIN only as an attribute, and map to each provider through a static per-MIC suffix table. Wealthfolio, a Rust/Tauri portfolio app, does exactly this in its `exchanges.json`, covering 76 exchanges ([Wealthfolio exchanges.json](https://github.com/wealthfolio/wealthfolio/blob/main/crates/market-data/src/resolver/exchanges.json)). An ISIN alone cannot tell SAP on Xetra (EUR) from the SAP ADR on NYSE (USD). Yahoo's suffixes are `.IS`, `.DE`, `.PA`, `.AS` and `.L`, with no suffix for US listings ([Yahoo Help](https://help.yahoo.com/kb/SLN2310.html)). EODHD uses its own exchange codes rather than MICs, such as `SAP.XETRA` and `BP.LSE` ([EODHD docs](https://eodhd.com/financial-apis/api-for-historical-data-and-volumes)). Twelve Data takes a bare symbol plus `mic_code` ([PP TwelveDataQuoteFeed](https://github.com/portfolio-performance/portfolio/blob/master/name.abuchen.portfolio/src/name/abuchen/portfolio/online/impl/TwelveDataQuoteFeed.java)). Allow a per-instrument override for symbols that break the rule. For users who only know an ISIN, OpenFIGI maps ISIN plus `micCode` to a ticker, keyless at 25 requests/min, and its identifiers may be redistributed freely ([OpenFIGI API](https://www.openfigi.com/api/documentation), [OpenFIGI ToS](https://www.openfigi.com/docs/terms-of-service)).

**Currency units.** Read the quote currency **from each response, not from the exchange**. On 2026-11-12 Yahoo returned **SHEL.L in `GBp` (3657.5 pence)** but **VUSA.L in `GBP` (108.535)**, both on the same LSE ([live call](https://query1.finance.yahoo.com/v8/finance/chart/SHEL.L?range=1d&interval=1d)). Twelve Data labels VOD as `GBp` ([live](https://api.twelvedata.com/stocks?symbol=VOD&show_plan=true)), and Alpha Vantage uses `GBX` ([live](https://www.alphavantage.co/query?function=SYMBOL_SEARCH&keywords=tesco&apikey=demo)). EODHD's `/eod` response has no currency field at all, so its unit has to come from the MIC table. Normalise `GBp`/`GBX` to GBP by dividing by 100 at ingestion, and store both the major unit and the original provider unit. Portfolio Performance's `convertBritishPounds` does the same in both directions ([PP YahooFinanceQuoteFeed](https://github.com/portfolio-performance/portfolio/blob/master/name.abuchen.portfolio/src/name/abuchen/portfolio/online/impl/YahooFinanceQuoteFeed.java)). A ratio near 100 between two providers' prices for the same day signals a unit mismatch, not a market move. Conversion to the display currency then reuses the app's existing per-day fiat rates: Frankfurter's 30 currencies include TRY ([Frankfurter currencies](https://api.frankfurter.dev/v1/currencies)).

**Raw versus adjusted close.** Value holdings with the **raw traded close** multiplied by the share count held on that day, and record splits and bonus issues against the holding. Adjusted closes are recomputed whenever a new dividend arrives, so past values change. EODHD defines `close` as "as traded — not adjusted" and warns that `adjusted_close` is rewritten over time ([EODHD docs](https://eodhd.com/financial-apis/api-for-historical-data-and-volumes)). MarketData.app's candles matched EODHD's adjusted series, so they are adjusted by default ([live](https://api.marketdata.app/v1/stocks/candles/D/AAPL/?from=2026-06-01&to=2026-06-03)). borsapy has to reverse TradingView's split adjustment using İş Yatırım's split data ([borsapy releases](https://github.com/saidsurucu/borsapy/releases)). The notes leave one point open: whether Yahoo's `quote.close` is unadjusted around splits as well as dividends. In the test windows it equalled `adjclose`, but no corporate action fell inside them. For İş Yatırım, the notes label the `HG_*` fields as raw and the `HGDG_*` fields as adjusted, but they did not test the two sets against a split. Verify both providers against a known split or bonus issue before relying on them. Caching protects against most of this risk: **a close stored once in `history.json` cannot later be silently re-adjusted**. Store an `adjusted` flag with every value, and never mix adjusted and raw values in one series.

**Weekends, holidays and timestamps.** For valuation date D, use the **latest bar whose exchange-local trading date is on or before D**, and show its as-of date. No holiday calendar is needed. Key bars by local date, not UTC date. Yahoo's BIST timestamps are session *starts* at 06:30 UTC ([live call](https://query1.finance.yahoo.com/v8/finance/chart/THYAO.IS?period1=1762128000&period2=1762560000&interval=1d)), and a US close at 16:00 New York is 21:00 UTC. Wealthfolio stores local close times of 16:00 for XNYS, 16:30 for XLON and 18:00 for XIST ([Wealthfolio exchanges.json](https://github.com/wealthfolio/wealthfolio/blob/main/crates/market-data/src/resolver/exchanges.json)). Use them to decide when today's bar becomes final and cacheable. Before that point, treat today's price as provisional, because Yahoo has served NaN bars before the open. Skip `null` entries in Yahoo's close arrays. If the "latest bar ≤ D" is more than a few trading days older than D, as with Yahoo's missing 2026-08-28 session, ask the next provider for that date. Do not count weekends and holidays as provider failures.

**Failure handling.** Wealthfolio's registry is a good template for a ureq client ([Wealthfolio retry.rs](https://github.com/wealthfolio/wealthfolio/blob/main/crates/market-data/src/errors/retry.rs), [circuit_breaker.rs](https://github.com/wealthfolio/wealthfolio/blob/main/crates/market-data/src/registry/circuit_breaker.rs)). It sorts errors into retry classes. An unknown symbol (Yahoo 404) means stop. A 429 or a timeout means fail over with a penalty. "No data for this range" means try the next provider without a penalty. A circuit breaker opens after 5 consecutive failures, retries after 60 s, and closes after 2 successes. Responses should be validated by **content type and shape** as well as status. Stooq served HTML with a 200, İş Yatırım reports errors as `"ok":false` with a 200, and Twelve Data returns error JSON. Each fetched price should also pass OHLC sanity checks (`low ≤ close ≤ high`, positive values) before it can override a cached value ([Wealthfolio validator.rs](https://github.com/wealthfolio/wealthfolio/blob/main/crates/market-data/src/registry/validator.rs)). Record which provider supplied each stored price, so the UI can mark fallback or manual values.

## Conclusion

The main engineering risk is not reaching a price endpoint but normalising what comes back. Units differ per instrument even within one exchange (GBp versus GBP on LSE), providers silently return adjusted or split-adjusted series, and Yahoo's timestamps are session starts rather than closes. A feed that gets the canonical (ticker, MIC) key, unit normalisation and the "last local bar ≤ D" rule right can swap providers freely. A feed that doesn't will produce valuations that jump by a factor of 100 or drift after every dividend, whichever provider it uses. Freezing past closes in the history cache makes the design robust: once a holding is backfilled, a Yahoo outage costs only today's price, which every fallback in the chain can supply.

The ranking of markets is the reverse of what one might expect. BIST, with no free official API, has the deepest keyless redundancy: Yahoo, İş Yatırım history and TradingView current prices, all cross-validated to the kuruş. The EU, with MiFID II-mandated free delayed data, has no keyless history fallback at all, because Euronext encrypts its payloads, Stooq is gone and Börse Frankfurt gates its history. That makes the BYOK slot, and specifically EODHD, which covers Xetra, Euronext and LSE within a one-year free window, the most valuable optional feature for EU users. Before the app commits to EODHD as its universal BYOK provider, one live check with a registered free key against `THYAO.IS` would settle whether it also covers BIST.
